### 综合案例：内部网络服务及日志存储综合任务

#### **案例背景**

​	某企业计划在三台服务器上部署一套综合服务环境，旨在实现网络互通、服务高可用、日志集中管理及磁盘高效利用。企业要求各服务器协同工作，同时为未来的扩展提供便利。

服务器规划：

- **node1**：主业务服务器，提供Web服务。
- **node2**：辅助服务器，负责DNS解析功能。
- **node3**：集中日志服务器，存储所有服务器的日志。

------

#### **任务目标**

1. **网络配置**：实现静态IP配置及互通。
2. **负载均衡与DNS解析**：配置内部域名解析。
3. **日志管理**：集中收集所有服务器日志，并存储在逻辑卷中。
4. **磁盘管理**：使用LVM管理日志存储，优化磁盘空间利用。

------

#### **任务一：网络配置**

1. **需求**：
   - 使用 `192.168.88.0/24` 网络。
   - 为三台服务器配置静态IP：
     - node1: `192.168.88.170`
     - node2: `192.168.88.171`
     - node3: `192.168.88.172`
2. **操作要求**：
   - 配置静态IP并设置网关和DNS。
   - 验证网络连通性，确保三台服务器可以互相Ping通 同时SSH保持通畅。



```properties
1- 修改IP地址
2- 修改hosts内容
3- 测试网络是否通畅
4- 测试ssh是否可以正常免密
```

------

#### **任务二：DNS解析**

1. **需求**：
   - 设置 node2为内部DNS服务器：
     - `web.internal.local` -> `192.168.88.170`
     - `log.internal.local` -> `192.168.88.172`
2. **操作要求**：
   - 部署BIND服务以支持内部域名解析。
   - 测试域名解析功能。

```properties
1- 在node2安装DNS服务器
2- 在node2中配置dns： 主配置文件  正反向解析文件
3- 校验配置文件的语法是否正确
4- 启动DNS服务器
5- 放行防火墙


在node1、node2、node3将DNS修改为 node2的地址

分别在node1和node3测试是否可以ping通对应域名
```



------

#### **任务三：日志集中管理**

1. **需求**：
   - **node3** 接收 **node1** 和 **node2** 的日志。
2. **操作要求**：
   - 在 node1 和 node2配置RSYSLOG远程日志转发：
     - `*.info` 日志转发到 **node3**。
   - 在 **node3** 配置RSYSLOG接收远程日志。
   - 验证日志转发及存储功能。

```properties
1- node1 和node2 修改rsyslog的配置文件: /etc/rsyslog.conf
	增加规则配置： 
		*.info               @@log.internal.local:514

2- 重启 node1和node2的rsyslog服务

3- 配置node3的rsyslog的配置文件 : /etc/rsyslog.conf
	修改配置：  放开接收远端tcp日志的配置信息
4- 重启node3的rsyslog的日志服务
5- 放行端口 514
6- 测试： 在node1和node2 分别通过logger写入info及以上的级别日志 观察node3的/var/log/message 是否可以收到日志
```



------

#### **任务四：磁盘管理与日志存储优化**

1. **需求**：
   - 在使用 **node3** 构建一块独立磁盘 创建逻辑卷 `lv_logdata`，挂载到 `/var/log`。
   - 初始逻辑卷大小为15GB，并支持动态扩展。
   - 尝试对其进行扩容到30GB
2. **操作要求**：
   - 创建物理卷、卷组和逻辑卷：
     - 物理卷：`/dev/sdb`
     - 卷组：`vg_logs`
     - 逻辑卷：`lv_logdata`，大小为15GB。
   - 格式化并挂载逻辑卷到 `/var/log`。
   - 配置开机自动挂载。
   - 验证存储在新挂载点是否正常。
   - 最后， 尝试扩容逻辑卷

------

#### **任务五：综合验证**

**验证步骤**：

- 测试三台服务器的网络连通性。
- 使用域名 `web.internal.local` 访问Web服务。
- 使用 `logger` 命令生成日志，验证日志是否成功存储到 **node3** 的 `/var/log`。
- 检查逻辑卷的可用空间及扩展能力。
